# Known limitations
- Prototype data is in-memory; refresh resets everything. Wallet/payments/bookings are simulated.
- Flights are deterministic simulations, not a real provider.
- Backend: auth, trips, notifications, reviews, catalogue, bookings, payments (mock provider), refunds, wallet reads, settlement and RBAC are implemented and covered by integration tests on a real MySQL 8.4 in CI. Financial transactions are OFF by default (`FINANCIAL_TRANSACTIONS_ENABLED=false`) and the payment provider is a mock.
- In BETA/PRODUCTION the account snapshot (bookings, wallet, notifications, reviews, **catalogue**) and **checkout** come from the API: the app books a real catalogue item (`POST /bookings`), opens a payment intent, and waits for the server's status. In non-production environments with the mock provider a simulated provider event is delivered through the real webhook path (`POST /dev/payments/simulate`, which does not exist in production). With a real provider the booking stays `PENDING_PAYMENT` until the provider confirms.
- Checkout limits: one unit per booking and the item's next available date (no date/quantity picker yet); only catalogue items can be booked for real (trip packages and flights from the prototype data show "not available for real booking here"); Sabai Wallet cannot pay (refund credit only); the QR is not rendered yet (the server returns `qr_payload`); catalogue ratings/review counts are not available (shown as 0); the TOUR and TRANSPORT categories display as "attraction".
- The cancel screen shows an indicative refund equal to the amount paid; inside the 48-hour window the server refuses the request ("no refund is due") and the app shows the error instead of marking the booking cancelled.
- Trips are persisted through the repository; community, coupons, support tickets and calendar events remain local state (no endpoints yet).
- Only BootGate and auth have UI tests; most feature screens are covered by build/lint only.
- Coverage is not measured; `@vitest/coverage-v8` is not installed.
- Repo root has a committed `node_modules`; the superseded `sabai-travel-app-prototype.jsx` remains at repo root.
- Bundle is a single 395 kB chunk (no route splitting).
