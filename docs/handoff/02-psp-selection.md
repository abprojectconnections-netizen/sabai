# Sabai — คู่มือเลือกผู้ให้บริการชำระเงิน (PSP) และขอ sandbox

**หมายเหตุสำคัญ:** รายชื่อด้านล่างเป็น "ผู้สมัครที่ควรสอบถาม" ไม่ใช่คำแนะนำ ทีมพัฒนา **ยังไม่ได้ตรวจสอบ** ค่าธรรมเนียม ฟีเจอร์ หรือเงื่อนไขของรายใดทั้งสิ้น ทุกข้อต้องยืนยันเป็นลายลักษณ์อักษรจากผู้ให้บริการ

ผู้สมัครเบื้องต้น (ยังไม่ยืนยัน): Opn Payments (Omise), 2C2P, GB Prime Pay, Stripe

## 1) สิ่งที่ระบบ Sabai ต้องการจาก PSP (ตามโค้ดปัจจุบัน)
อินเทอร์เฟซอยู่ที่ `backend/internal/finance/payment/provider.go` (มี Mock ใช้ทดสอบ) PSP จริงต้องรองรับ:
- สร้างรายการชำระเงิน (payment intent/charge) พร้อมรหัสอ้างอิงของเรา และรองรับ idempotency
- Webhook ที่ **ลงลายเซ็น** และมี timestamp (เรากันเหตุการณ์เก่า/ซ้ำ)
- คืนเงินบางส่วนและเต็มจำนวนผ่าน API (ผูกกับรายการเดิม)
- ไฟล์รายการเคลื่อนไหว/statement สำหรับกระทบยอด (CSV หรือ API) — runner: `cmd/reconcile`
- สกุลเงิน THB; ช่องทางที่ต้องการ: PromptPay QR, บัตร, (ตัวเลือก) wallet/ผ่อน
- ชุดทดสอบ sandbox ที่จำลองความล้มเหลว ถูกปฏิเสธ และ refund ได้

## 2) คำถามที่ต้องถามทุกราย
**ธุรกิจ/กฎหมาย**
1. รองรับโมเดล marketplace/แยกจ่ายให้พาร์ทเนอร์หรือไม่ (split payment/sub-merchant) และเงินพักอยู่ที่ใคร
2. ผู้ให้บริการได้รับอนุญาตตามกฎหมายไทยอะไรบ้าง (ขอเอกสาร) และบทบาทของแพลตฟอร์มเรา ต้องมีใบอนุญาตเองหรือไม่ (ส่งต่อฝ่ายกฎหมาย ข้อ ก1)
3. เอกสารเปิดบัญชีธุรกิจที่ต้องใช้ และระยะเวลาอนุมัติ
4. สินค้าท่องเที่ยว/จองล่วงหน้าถือเป็นธุรกิจความเสี่ยงสูงหรือไม่ มีเงินสำรอง (reserve) หรือไม่
**ค่าใช้จ่าย**
5. ค่าธรรมเนียมต่อช่องทาง (PromptPay บัตรในประเทศ/ต่างประเทศ) ค่าติดตั้ง ค่ารายเดือน ขั้นต่ำ
6. ค่าธรรมเนียมถูกคืนเมื่อ refund หรือไม่ ค่า chargeback
7. รอบโอนเงินเข้าบัญชีเรา (T+?) และค่าธรรมเนียมการโอน
**เทคนิค**
8. กลไก idempotency, รูปแบบลายเซ็น webhook, นโยบาย retry, rate limit
9. refund บางส่วนหลายครั้งต่อรายการ และขีดจำกัดเวลา
10. รูปแบบ/ความถี่ statement และรหัสอ้างอิงที่ตรงกับ webhook
11. SLA/uptime, ช่องทางซัพพอร์ตภาษาไทย, ประวัติเหตุขัดข้อง
12. มาตรฐานความปลอดภัย (PCI DSS ระดับใด) และว่าเราจะไม่แตะข้อมูลบัตรเอง (ใช้หน้า/ช่องที่ผู้ให้บริการโฮสต์)

## 4) เอกสารที่เตรียมไว้ก่อนสมัคร (เช็กลิสต์)
- [ ] หนังสือรับรองบริษัท (อายุไม่เกิน 6 เดือน) บัญชีรายชื่อผู้ถือหุ้น
- [ ] บัตรประชาชนกรรมการผู้มีอำนาจ + หนังสือมอบอำนาจ (ถ้ามี)
- [ ] ทะเบียนภาษีมูลค่าเพิ่ม (ภ.พ.20) ถ้าจดแล้ว
- [ ] สมุดบัญชีธนาคารบริษัท/หน้า statement
- [ ] URL เว็บไซต์/แอป, ข้อกำหนดการใช้งาน, นโยบายยกเลิก/คืนเงิน, นโยบายความเป็นส่วนตัว (**ต้องผ่านฝ่ายกฎหมายก่อน**)
- [ ] คำอธิบายโมเดลธุรกิจและเส้นทางเงิน (ใช้ส่วน "สรุประบบ" ในเอกสารฉบับที่ 1)
- [ ] ประมาณการยอดขาย/จำนวนรายการต่อเดือน

## 6) ขั้นตอนหลังได้ sandbox
1. ให้ทีมพัฒนาเขียน adapter ที่อินเทอร์เฟซ `payment.Provider` (ตั้ง `PAYMENT_PROVIDER` เป็นค่าใหม่)
2. รันชุดทดสอบเดิม + ทดสอบ webhook ซ้ำ/เก่า/ลายเซ็นผิด + refund บางส่วน
3. กระทบยอด sandbox ด้วย `cmd/reconcile`
4. **ห้ามเปิดเงินจริง** จนกว่า `go_live_approvals` ทั้ง 4 ฝ่าย (PSP, LEGAL, ACCOUNTING, SECURITY) ลงนาม และเปลี่ยน `FINANCIAL_TRANSACTIONS_ENABLED=true`
