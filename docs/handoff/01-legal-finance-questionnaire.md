# Sabai — แบบสอบถามขอคำตัดสินจากฝ่ายกฎหมาย บัญชี และการเงิน

**วัตถุประสงค์:** ระบบการเงินของ Sabai (จอง ชำระเงิน คืนเงิน กระเป๋าเงิน ชำระเงินให้พาร์ทเนอร์) สร้างเสร็จและทดสอบแล้วบน provider จำลอง แต่ **ยังเปิดใช้เงินจริงไม่ได้** จนกว่าจะได้คำตอบด้านล่าง
ทุกข้อมี "ค่าเริ่มต้นที่ระบบใช้ตอนนี้" ซึ่งเป็นข้อเสนอของทีมพัฒนา **ไม่ใช่การตัดสินทางกฎหมายหรือบัญชี** โปรดตอบว่า เห็นด้วย / ปรับเป็น … / ยังไม่ตัดสิน

**สรุประบบสั้นๆ:** ลูกค้าจ่ายเงินให้แพลตฟอร์ม → แพลตฟอร์มหักค่าคอมมิชชัน → จ่ายพาร์ทเนอร์เป็นรอบรายสัปดาห์ (วันอังคาร) หลังพ้นช่วงตรวจสอบ 7 วัน ลูกค้ายกเลิกได้ตามนโยบาย เงินคืนกลับช่องทางเดิม กระเป๋าเงิน Sabai เก็บได้เฉพาะ "เครดิตเงินคืน" (ไม่มีเติมเงิน โอน หรือถอน)

## ส่วน ก — ฝ่ายกฎหมาย

| # | คำถาม | ค่าเริ่มต้นที่ระบบใช้ตอนนี้ | คำตอบ |
|---|---|---|---|
| ก1 | **การถือเงินแทนพาร์ทเนอร์:** การที่แพลตฟอร์มรับเงินจากลูกค้าแล้วจ่ายพาร์ทเนอร์ภายหลัง ต้องขออนุญาต/ขึ้นทะเบียนกับธนาคารแห่งประเทศไทย (พ.ร.บ. ระบบการชำระเงิน พ.ศ. 2560) หรือไม่ หรือควรให้ผู้ให้บริการชำระเงินแบบ marketplace กระจายเงินให้พาร์ทเนอร์โดยตรง | ยังไม่ได้ข้อสรุป; ระบบทำงานแบบแพลตฟอร์มรับเงินก่อน | |
| ก2 | **ข้อความขอความยินยอม** ให้ลูกค้ารับเงินคืนเป็นเครดิตในกระเป๋าเงิน (ข้อความภาษาไทย เวอร์ชัน วันที่มีผล) | **ปฏิเสธการคืนเป็นเครดิตทั้งหมด** จนกว่าจะมีข้อความที่ฝ่ายกฎหมายอนุมัติ | |
| ก3 | กระเป๋าเงินจะใช้จ่ายค่าจองใหม่ได้หรือไม่ หรือเป็นเครดิตเงินคืนเท่านั้น | เครดิตเงินคืนเท่านั้น ไม่มีเติมเงิน/โอน/ถอน/ใช้ชำระ | |
| ก4 | **ใครเป็นผู้ขาย (seller of record)** และใครเป็นผู้ออกเอกสารต่อลูกค้า: แพลตฟอร์มในฐานะตัวแทน หรือพาร์ทเนอร์ | พาร์ทเนอร์เป็นผู้ขาย; **ระบบไม่ออกใบกำกับภาษี** จนกว่าจะอนุมัติผู้ออก | |
| ก5 | ระยะเวลาเก็บเอกสารแต่ละประเภท (ใบกำกับภาษี สัญญา บันทึกการยินยอม log การเงิน ข้อมูลส่วนบุคคลที่เกี่ยวข้อง) | อนุมัติแล้วเฉพาะใบกำกับภาษี 5 ปี; ประเภทอื่นยังไม่กำหนด | |
| ก6 | ข้อความนโยบายยกเลิก/คืนเงินที่แสดงต่อลูกค้า และสัญญากับพาร์ทเนอร์ (ต้องผ่านการตรวจก่อนพาร์ทเนอร์ ACTIVE) | ระบบไม่ยอมให้สัญญามีผลจนกว่าจะบันทึกว่าฝ่ายกฎหมายตรวจแล้ว | |
| ก7 | PDPA: ฐานทางกฎหมายและระยะเก็บข้อมูลส่วนบุคคลของลูกค้า/พาร์ทเนอร์ รวมถึงการเก็บเลขบัญชีธนาคารพาร์ทเนอร์ (เข้ารหัสแล้ว) | ยังไม่มีนโยบายความเป็นส่วนตัวฉบับอนุมัติ | |

## ส่วน ข — ฝ่ายบัญชี / ภาษี

| # | คำถาม | ค่าเริ่มต้นที่ระบบใช้ตอนนี้ | คำตอบ |
|---|---|---|---|
| ข1 | ราคาที่แสดงต่อลูกค้า **รวม VAT หรือยังไม่รวม** และอัตราภาษีต่อหมวดสินค้า (ที่พัก ทัวร์ ตั๋ว รถรับส่ง) | ไม่คำนวณภาษี; สถานะ "ยังไม่ยืนยัน" | |
| ข2 | ค่าคอมมิชชันของแพลตฟอร์ม: ฐานภาษี และใครออกใบกำกับภาษีค่าคอมมิชชันให้พาร์ทเนอร์ | ยังไม่ออกเอกสาร | |
| ข3 | เมื่อมี refund หลังจ่ายพาร์ทเนอร์แล้ว ต้องออกใบลดหนี้อย่างไร | ระบบมีโครงใบลดหนี้ที่ผูกกับใบเดิม แต่ยังไม่ออกเอกสารจริง | |
| ข4 | การรับรู้รายได้ของแพลตฟอร์ม (เฉพาะค่าคอมมิชชัน หรือยอดเต็ม) และการบันทึกเงินที่ยังไม่จ่ายพาร์ทเนอร์ | ระบบแยกยอดขายรวม ค่าคอมมิชชัน และยอดสุทธิรายพาร์ทเนอร์ | |
| ข5 | รูปแบบไฟล์/รายงานที่ฝ่ายบัญชีต้องการสำหรับปิดงวด และการกระทบยอดกับ provider | มี runner กระทบยอด (นำเข้า CSV) | |

## ส่วน ค — ฝ่ายการเงิน / ผู้บริหาร

| # | คำถาม | ค่าเริ่มต้นที่ระบบใช้ตอนนี้ | คำตอบ |
|---|---|---|---|
| ค1 | **วงเงินอนุมัติ refund** | ข้อเสนอ: อัตโนมัติ ≤ 3,000; เจ้าหน้าที่ refund ≤ 5,000; ผู้จัดการการเงิน ≤ 50,000; เกินนั้นต้องผู้อนุมัติ 2 คน รวม CFO | |
| ค2 | **นโยบายยกเลิก:** ยกเลิกฟรีกี่ชั่วโมงก่อนใช้บริการ และคืนกี่ % หลังพ้นช่วง | ฟรีภายใน 48 ชม. (ก่อนบริการ) คืนเต็มยอดที่ชำระ; หลังพ้นช่วง: ไม่คืน | |
| ค3 | ค่าคอมมิชชัน: อัตราเริ่มต้น อัตรารายหมวด รายพาร์ทเนอร์ ลำดับความสำคัญ และกรณีการจองผสมหลายหมวด | 5% เริ่มต้น; พาร์ทเนอร์ > หมวด > ค่าเริ่มต้น; การจองผสมหมวดใช้ พาร์ทเนอร์/ค่าเริ่มต้น | |
| ค4 | เมื่อ refund หลังจ่ายพาร์ทเนอร์ไปแล้ว พาร์ทเนอร์คืนค่าคอมมิชชันหรือไม่ และหักจากรอบถัดไปหรือเรียกเก็บแยก | พาร์ทเนอร์คืนส่วนฐานและค่าคอมมิชชันตามสัดส่วนที่ refund ที่อัตราเดิม หักในรอบถัดไป; ถ้ายอดสุทธิติดลบ ระบบเลื่อนไปรอบหน้า | |
| ค5 | รอบจ่ายพาร์ทเนอร์ และช่วงตรวจสอบหลังวันใช้บริการ | รายสัปดาห์ (อังคาร), 7 วัน | |
| ค6 | ผู้ที่เตรียม ตรวจ และอนุมัติรอบจ่ายเงิน | ต้องเป็นคนละคนกันทั้งสามบทบาท (บังคับด้วยระบบ) | |
| ค7 | ค่าบริการแพลตฟอร์มที่เก็บจากลูกค้า | ไม่มี (ลูกค้าจ่ายเท่าราคาที่แสดง) | |
| ค8 | ช่วงเวลากันที่นั่งระหว่างรอชำระเงิน | 15 นาที | |
| ค9 | นิยาม "พาร์ทเนอร์ความเสี่ยงสูง" (ไม่อนุมัติ refund อัตโนมัติ) | พาร์ทเนอร์ที่ถูกตั้ง risk = HIGH | |
| ค10 | **ผู้อนุมัติเปิดใช้งานจริง (go-live)** ต้องมี 4 ฝ่ายลงนามบันทึก: ผู้ให้บริการชำระเงิน กฎหมาย บัญชี ความปลอดภัย | ระบบไม่ยอมเปิด provider จริงถ้ายังไม่ครบ | |

## ส่งคำตอบกลับอย่างไร
ตอบในตารางนี้โดยตรง หรือส่งเป็นรายการ "ข้อ → คำตอบ → วันที่มีผล → ผู้อนุมัติ" ทีมพัฒนาจะบันทึกค่าลงฐานข้อมูลแบบมีเวอร์ชันและผู้อนุมัติ (ไม่แก้ค่าในโค้ด) ข้อที่ยังไม่ตัดสินจะคงสถานะปิดไว้ (ปลอดภัยไว้ก่อน)
